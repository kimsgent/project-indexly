## Release v2.1.8 (2026-11-20)

Indexly v2.1.8 makes optional Homebrew-managed extras easier to inspect and clean up while strengthening the filesystem checks that protect managed paths. It also improves Rename Watch recovery when a durable record conflicts with the current filesystem state.

### Managed extras cleanup and filesystem safety

- Inspect the active runtime and managed extras state, then list obsolete managed environments before any deletion.
- Cleanup remains dry-run first and requires explicit confirmation before it removes an obsolete managed environment. The active runtime environment is never selected for cleanup.
- Managed extras operations reject symlinked and filesystem reparse-point paths, including cleanup candidates, their ancestors, recovery remnants, and nested size traversal entries.
- Existing per-scope locks continue to coordinate cleanup with older managed runtimes.

### Rename Watch recovery

- A recovery conflict now preserves its durable evidence and marks only the affected source as blocked.
- Other eligible files can continue through the configured Rename Watch workflow instead of being stopped by an unrelated ambiguous recovery record.
- See [Rename Watch](/en/documentation/rename-watch/) and [Operate Rename Watch as a Service](/en/documentation/rename-watch-service-operation/) for operational guidance.

### Release and packaging notes

- The release documentation now has a tracked navigation graph and validation script so related source, test, and Hugo guidance can be reviewed together.
- Homebrew Formula audit validation runs in an isolated tap. The Formula is updated from the built release artifact during the release process rather than by this release-preparation change.
- No runtime or development dependency declarations were added in this release.

### Compatibility

- Python 3.11 or newer remains required.
- There are no breaking changes in this release.
