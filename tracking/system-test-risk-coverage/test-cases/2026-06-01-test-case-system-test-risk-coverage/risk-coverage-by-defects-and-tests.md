# Risk Coverage by Defects and Tests

Local worksheet. Created on 2026-06-01 from branch `codex/system-test-risk-coverage`.

This is a seed risk and defect-coverage view for Indexly. No defect database was queried in this exercise, so `IDX-RISK-*` entries are risk placeholders. When a real bug exists, replace or link the placeholder with the real issue/defect ID.

## Risk Priority Scale

| RPN Band | Meaning                                                                                                                                          | Default Action                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1-5      | Critical/high risk. Regression setback, data loss, wrong analysis result, destructive filesystem/database behavior, or release/install breakage. | Must have regression tests and targeted system tests before release. |
| 6-10     | Significant risk. Broken workflow, missing optional dependency guidance, audit trace gap, or cross-module drift.                                 | Add or run focused regression and manual workflow tests.             |
| 11-17    | Moderate risk. Feature-specific failure with workaround or limited blast radius.                                                                 | Cover with suite-level regression or exploratory tests.              |
| 18-25    | Lower risk. Cosmetic, documentation, or isolated behavior.                                                                                       | Cover opportunistically or with smoke tests.                         |

Regression setbacks default to high risk because they prove previously working behavior can be broken by later changes.
